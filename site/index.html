hitron-cli: a live dashboard in your terminal

One static binary, no runtime, no login. It reads the modem's signal levels every second and shows them as big numbers, trend graphs, and a channel table that turns red when codewords go bad. Works on the CODA6X (CODA-60), CODA-57, and HT-EM5.

Get started

  1. Install

    Grab a binary from Releases (Linux, macOS, Windows; amd64 and arm64), or build it with Go 1.22+:

    $go install github.com/Netquor/hitron/cli/cmd/hitron-cli@latest
  2. Run it from any machine on the modem's LAN 
    $hitron-cli monitor

    It finds the modem at 192.168.100.1, works out which family it is, and starts the live view. Another address: hitron-cli monitor 192.168.0.1. No terminal UI wanted: hitron-cli stats --once prints a text report and --json a snapshot.

  3. Press h for help

Codewords you can read at a glance

Every channel shows corrected and uncorrectable codewords as one column, 13/711 98.20%, coloured green when clean and red when not. The big tile at the top rolls the whole modem into one number. Lease and uptime read as 5 days and 1 h 58 m, and the event log is rewritten into plain sentences, such as a profile change shown as 12 → 6.

A spectrum analyser and constellation, built in

On CODA6X modems the cable modem's own tuner is exposed. Press 2 for a 6 MHz live spectrum capture around any downstream channel, or 3 for the I/Q constellation with MER. The modem has one tuner, so captures run one at a time; use [ and ] to step through channels.

Six themes, one key

Press t to cycle neon, synthwave, dracula, nord, gruvbox, and matrix. The gradient background needs a 24-bit colour terminal and turns itself off otherwise; b toggles it.

Reboot that cannot happen by accident

Press x (or click the Reboot button) and a dialog asks you to type the word reboot. Nothing is sent before that, and Esc cancels. The CODA6X needs no username or password from the LAN, so the dialog does not ask for one. Factory reset and hard reset are deliberately not in the dashboard; they stay as separate commands.

Source, flags, and the full command list: cli/README.md. Read-only by design: the dashboard polls the same endpoints the modem's own status page uses.

End-to-end in four commands

From a clean checkout to a dashboard. The long version is in docs/GETTING-STARTED.md.

  1. 1

    Install and prove the device answers

    python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
hitron coda60 192.168.100.1 | head

    Read routes work without a login on the analyzed firmware. Writes need hitron coda60-… and --yes-really-do-this. No Python? The standalone Go client prints the same snapshot from one binary.

  2. 2

    Start the exporter

    hitron-exporter --port 9877 \
  --coda60 192.168.100.1 \
  --ht-em5 192.168.0.212 \
  --coda57 192.168.100.2

    Also serves /healthz, /api/v1/samples, and /api/v1/logs.

  3. 3

    Point Prometheus at it

    scrape_configs:
  - job_name: hitron
    static_configs:
      - targets: ["192.168.1.10:9877"]

    A ready-made stack lives in deploy/compose.yaml.

  4. 4

    Import the dashboard

    curl -O https://raw.githubusercontent.com/Netquor/hitron/main/dashboards/hitron-coda6x.json
# Grafana → Dashboards → New → Import → upload

    Or run hitron grafana --dir deploy/grafana for provisioning.

API console

Pick an operation, fill the path, send it. When this page is served by hitron site, the base URL is /proxy and the browser never touches the device directly.

Using the console in your browser

  1. Start the local proxy (see Run the API console locally) and open http://127.0.0.1:8000. This hosted page cannot reach your modem; the local copy can.
  2. Leave the base URL as /proxy. On the CODA6X, reads need no login. For writes, enter the modem's password and press Login via proxy.
  3. Pick an operation. Type in the filter box (try DsInfo or Log) or narrow by tag in the dropdown, then click a result.
  4. Send it. Fill any parameters, press send, and read the status, timing, and JSON in the Response panel. GET /1/Device/CM/DsInfo also feeds the live charts below.
  5. Prefer a terminal? The same data is one command away with hitron-cli.

Ten-minute Grafana path

  1. Copy deploy/compose.yaml, adjust the device IPs in deploy/prometheus/prometheus.yml, then docker compose up -d.
  2. Open Grafana at http://localhost:3000 (admin / admin on first boot).
  3. Dashboards → Hitron → Hitron CODA6X. The datasource and dashboard are provisioned.
  4. Set the source template variable to your exporter target name.
  5. Alerts → Alert rules → Hitron. Silence or tune the power envelope to your carrier.

One collector, four outputs

The same normalized series feed Prometheus, Telegraf, OpenTelemetry, and plain JSON. No second mapping table to rot.

hitron-exporter --port 9877 --coda60 192.168.100.1
curl -s http://127.0.0.1:9877/metrics | head

# modem_downstream_channel_power_dbmv{source="192.168.100.1",channel_id="1"} 8.098
# modem_downstream_channel_snr_db{source="192.168.100.1",channel_id="1"} 43.377
# modem_upstream_channel_power_dbmv{source="192.168.100.1",channel_id="10"} 31.0
# hitron_exporter_up{source="192.168.100.1",kind="coda60"} 1
# /etc/telegraf/telegraf.conf
[[inputs.exec]]
  commands = ["/opt/hitron/bin/hitron-exporter --coda60 192.168.100.1 --once --format telegraf"]
  data_format = "influx"
  interval = "30s"
  timeout = "25s"

[[outputs.influxdb_v2]]
  urls = ["http://influxdb:8086"]
  token = "$INFLUX_TOKEN"
  organization = "home"
  bucket = "hitron"

Telegraf consumes the Influx line protocol on stdout; no listener or plugin is required.

hitron-exporter --coda60 192.168.100.1 \
  --otlp-endpoint http://otel-collector:4318/v1/metrics

# The exporter posts OTLP/HTTP JSON. Point an otlphttp exporter at your backend:
exporters:

    endpoint: https://otlp.example.com

    metrics:
      receivers: [otlp]
